## Findings and corrections

1. **High: stateful modules have no callable initialization contract.** The original MIS describes empty registries and loaded model configuration but provides neither initialization signatures nor guards. Its Assumptions sections are empty, for example [M5, lines 433–451](https://github.com/richy1337/Verity/blob/4fbb82c1a9e6eba73aee030862d16588af2094f6/docs/Design/SoftDetailedDes/MIS.tex#L433). Independent implementations could accept work before the detector or ownership registry exists. The follow-up defines abstract-object scope, common initialization, readiness checks, immutable configuration matching and typed state. M4 remains a stateless library.

2. **High: some operation signatures cannot supply what their semantics require.** [M2 preview, lines 247–275](https://github.com/richy1337/Verity/blob/4fbb82c1a9e6eba73aee030862d16588af2094f6/docs/Design/SoftDetailedDes/MIS.tex#L247) promises a disclosure but returns only modality and route, with no explicit policy version/eligibility record. M6 requires a worker lease for borrow but no operation issues one. The follow-up introduces ConsentPreview, makes hold return the lease, and states how M5 delegates it. Image provenance is carried separately within Signals so M9 can consume it without an undeclared input.

3. **Medium: constants are named but not given literal values.** The [M5 exported constants](https://github.com/richy1337/Verity/blob/4fbb82c1a9e6eba73aee030862d16588af2094f6/docs/Design/SoftDetailedDes/MIS.tex#L415) and other modules leave implementers to consult another document. The MIS checklist requires explicit values. The follow-up adds values/units, inclusive bounds, code-point text length and decimal image MB. It preserves the current SRS cleanup bound of **1.0 second**, with no persistent raw writes at any time. A separately identified design constant bounds safe delivery metadata to 60 seconds; it does not extend raw-content retention.

4. **Medium: previously required integration decisions remain unspecified.** The V&V Plan's Design Verification section explicitly calls for an authoritative extension-owned surface, a cross-origin image acquisition path and a real opinion/satire applicability mechanism. The original MG leaves [UI and protocol sections empty](https://github.com/richy1337/Verity/blob/4fbb82c1a9e6eba73aee030862d16588af2094f6/docs/Design/SoftArchitecture/MG.tex#L352). The follow-up selects a side panel, specifies optional-origin image capture with bounded reads and no arbitrary backend URL fetch, and makes genre applicability fail closed until a versioned gate and held-out evidence exist. It also carries the V&V Plan's coded non-guarantee limitation into the MIS. These are proposed design contracts, not claims of implemented functionality.

5. **Medium: lifecycle and evaluation contracts need explicit pass/fail conditions.** The original pending-state decision combines completion/abstention in prose, and M10 refers generally to FPR denominators. The follow-up mirrors the SRS's five disjoint guard rows, defines score validity before use, and gives the coverage and assessed/full-negative FPR formulas. Empty required populations and undefined metrics cannot pass. Model and baseline F1 use identical assessed IDs. The availability statement now follows NFT-8's health probes, with recovery and capacity verified separately.

6. **High: module-level implementation schedule is absent; document structure and traceability are incomplete.** Acronym sections, MG UI/protocol/database/timeline sections, and MIS Assumptions/Local Functions fields are empty. Revision tables lack a Developer(s) column. Some trace rows combine distinct requirements, and M10 is a software-decision module with no live behaviour-module caller without an explicit exception. The follow-up fills the objective design sections, separates requirement rows, names concrete revisions, adds captions and explains M10's offline-entry-point exception. Each anticipated change has one leaf owner; multiple changes may affect the same secret. Secrets are expressed as single decision phrases. The MG now gives all ten modules an owner, independent reviewer, target window, dependency and confidence check, followed by integration, the Jan 18 design freeze and the Rev 0 demonstration readiness gate. The MIS also explicitly locates staged content, service buffers, immutable models, display data and offline artifacts, with ownership transfer and local cleanup rules. The milestone READMEs link sources and PDFs.

7. **Still requires contributor input: reflection and historical verification.** The submitted [MIS Reflection section is empty](https://github.com/richy1337/Verity/blob/4fbb82c1a9e6eba73aee030862d16588af2094f6/docs/Design/SoftDetailedDes/MIS.tex#L776). The follow-up supplies an objective team synthesis for prompts 1–6, including limitations (LO_ProbSolutions) and alternatives (LO_Explores). It cannot supply truthful first-person accounts for the four members. Each member must add their actual experience and confirm the original AI tool/version and human-verification statements. The disclosure says Claude Fable 5.2, but the source commit credits Claude Opus 5.5; that discrepancy is explicitly flagged rather than guessed. The dated Codex disclosure distinguishes this agent review from those human claims. The supplied rubric makes reflection due five days after the original deadline (Nov 21 for the Nov 16 milestone). Question 7 follows the actual peer-module implementation and must link its PR and discuss both implementation directions if applicable.
