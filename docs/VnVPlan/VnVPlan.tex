\subsection{Identifier Conventions}\label{subsec:id-conventions}

\begin{itemize}[leftmargin=*]
    \item \texttt{C1}--\texttt{C7} denote the internal components defined in \HA{} Section~3. \SRS{} mandated constraints are written \texttt{SRS-C1}--\texttt{SRS-C6} to avoid a collision (for example, \texttt{SRS-C6} is encrypted transport; \texttt{C6} is the evidence engine).
    \item \texttt{S1}--\texttt{S4} denote the \SRS{} black-box subsystems (\SRS{} Table~13).
    \item \texttt{Class 1}--\texttt{Class 9} denote the input equivalence classes in \SRS{} Table~17.
    \item \texttt{FT-}$n$ are functional and safety system tests. \texttt{NFT-}$k$ verifies \texttt{NFR}$k$, so \texttt{NFT-7} verifies \hyperref[req:NFR7]{NFR7}. \texttt{UT-C}$k$ is the unit suite for component \texttt{C}$k$.
    \item \texttt{FX-*} identifiers name test fixtures listed in Appendix~\ref{subsec:fixtures}.
\end{itemize}

\section{General Information}\label{sec:general-info}

This section summarizes the system under test, states the objective of the plan and its priorities, and lists the companion documents.

\subsection{Summary}\label{subsec:summary}

\textbf{Verity} is a user-triggered desktop Chromium browser extension (\MVThree{}) paired with a Python FastAPI analysis service and an offline Command-Line Interface (\CLI{}) evaluation harness. Users select webpage text (\MinTextLength{} $\le L_T \le$ \MaxTextLength{}) or a static image (PNG, JPEG, WebP; \MinImageDim{} $\le W_I, H_I \le$ \MaxImageDim{}, $B_I \le$ \MaxImageSize{}) and receive an assessment of \AI{}-generation signals, manipulation signals, and provenance metadata (\EXIF{}, \CTwoPA{}). Verity does not issue truth or fraud verdicts. It operates across four black-box subsystems (\texttt{S1}--\texttt{S4}) and seven internal components (\texttt{C1}--\texttt{C7}):
\begin{enumerate}[leftmargin=*]
    \item \textbf{Scoped capture and pre-admission validation (\texttt{S1}, \texttt{S2}; \texttt{C1}, \texttt{C3}):} reads only the user-selected node, validates format, size, and magic bytes before admission, and rejects active content and decompression bombs.
    \item \textbf{Grounded signal analysis and abstention (\texttt{S3}; \texttt{C6}):} extracts signals and provenance metadata, tags every evidence item with a source type from $\mathcal{E}_{\text{src}}$, and returns \texttt{inconclusive} when signals are borderline, conflicting, or out of domain (opinion, satire, creative writing).
    \item \textbf{Lifecycle, isolation, and ephemeral privacy (\texttt{S1}, \texttt{S2}; \texttt{C2}, \texttt{C4}, \texttt{C5}):} enforces the five request states, binds each result to a \UUID{}v4 request identifier and session, never shows a low-risk summary on timeout or failure, writes no raw content to persistent storage or logs, and releases application-owned transient references within \MaxRetentionTime{}.
    \item \textbf{Offline benchmark and fairness auditing (\texttt{S4}; \texttt{C7}):} evaluates detectors on source-disjoint held-out corpora and reports selective and full-population Macro-$F_1$, coverage, \FPR{}, and \ESL{} and re-compressed image slices.
\end{enumerate}

\subsection{Objectives and Scope Priorities}\label{subsec:objectives}

\textbf{Objective.} The objective of this plan is to produce evidence, before the Final Demo, that Verity never gives a user false reassurance, never exposes or retains a user's selection without consent, never accuses an author, and produces output that non-expert users interpret correctly. Verification effort is allocated by hazard severity in \HA{} Table~5. The plan prioritizes five mission-critical qualities, in order:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Safe failure and honest uncertainty.} Timeouts, crashes, partial results, and weak signals map to \texttt{failed} or \texttt{inconclusive} and never to a low-risk summary (\hyperref[req:SR1]{SR1}, \hyperref[req:SR3]{SR3}, \hyperref[req:SR4]{SR4}, \texttt{INV2}; hazards \hyperref[haz:H2]{H2}, \hyperref[haz:H5]{H5}, \hyperref[haz:H6]{H6}).
    \item \textbf{Privacy and least-privilege access.} Only the selected item and user note are read; no transfer without consent; no persistent raw content; bounded cleanup; no cross-session access (\hyperref[req:SR8]{SR8}, \hyperref[req:SR9]{SR9}, \texttt{INV4}; \hyperref[haz:H4]{H4}, \hyperref[haz:H9]{H9}).
    \item \textbf{Bounded false accusation and fairness.} No accusatory wording; \FPR{} and coverage gates met; subgroup \FPR{} disclosed (\hyperref[req:SR2]{SR2}, \hyperref[req:NFR1]{NFR1}, \hyperref[req:NFR10]{NFR10}; \hyperref[haz:H1]{H1}, \hyperref[haz:H10]{H10}).
    \item \textbf{Security against untrusted web content.} No script execution, no prompt-injection control, no host-page tampering with consent or results, no stale-result overwrite (\hyperref[req:SR5]{SR5}--\hyperref[req:SR7]{SR7}; \hyperref[haz:H3]{H3}, \hyperref[haz:H7]{H7}, \hyperref[haz:H8]{H8}).
    \item \textbf{Non-expert comprehension.} Users correctly read status, uncertainty, and next steps (\hyperref[req:NFR2]{NFR2}; \hyperref[haz:H5]{H5}).
\end{enumerate}
Latency, portability, installability, and maintainability (\hyperref[req:NFR3]{NFR3}, \hyperref[req:NFR5]{NFR5}, \hyperref[req:NFR6]{NFR6}, \hyperref[req:NFR9]{NFR9}) are verified with one primary test each.

\textbf{Alignment with companion documents.}
\begin{itemize}[leftmargin=*]
    \item \textbf{\SRS{} \cite{VeritySRS2026}:} every \texttt{FR}, \texttt{NFR}, \texttt{NFR.E}, \texttt{SR}, and \SRS{} Table~17 input class maps to at least one system test (Section~\ref{subsec:traceability}). Thresholds use the \SRS{} Table~6 constants.
    \item \textbf{\HA{} \cite{VerityHA2026}:} every hazard \texttt{H1}--\texttt{H10} and every verification method listed in \HA{} Table~4 maps to a test or a non-dynamic activity (Table~\ref{TblNonDynamic}).
    \item \textbf{\MG{} and \MIS{} \cite{VerityMG2026,VerityMIS2026}:} unit suites \hyperref[ut:C1]{UT-C1}--\hyperref[ut:C7]{UT-C7} follow components \texttt{C1}--\texttt{C7} and will be expanded per access routine once the \MIS{} is complete.
\end{itemize}

\textbf{Out of scope, with justification.}
\begin{enumerate}[leftmargin=*]
    \item \textbf{Internal testing of third-party frameworks and browser engines.} FastAPI, Starlette, Pydantic, PyTorch, Hugging Face Transformers, Pillow, \texttt{c2pa-python}, and Chromium are maintained and tested upstream. We test our wrappers, configuration, and boundary contracts only.
    \item \textbf{Pretraining or auditing foundation models.} Under \texttt{SRS-C4} and \SRS{} G.6, Verity calibrates pretrained open-weight models. We verify behaviour on frozen held-out splits only.
    \item \textbf{Forensic memory zeroing and kernel-level testing.} Per assumption \texttt{A5} and \texttt{INV4}, privacy tests verify zero persistent writes and logical release of application-owned references within \MaxRetentionTime{}. User-space code cannot control OS paging or garbage-collector heap reuse.
    \item \textbf{Non-Chromium browsers and mobile platforms.} Per \texttt{SRS-C1} and \hyperref[req:NFR5]{NFR5}, testing targets Chrome, Edge, and Brave ($\ge 120$) on desktop macOS, Windows, and Ubuntu Linux. Firefox and Safari are future work.
\end{enumerate}

\subsection{SRS Verification}\label{subsec:srs-verif}

The \SRS{} \cite{VeritySRS2026} is verified in four stages before each revision (Rev 0 done; Rev 1 due with the Final documentation, Weeks 24--26).
\begin{enumerate}[leftmargin=*]
    \item \textbf{Executable specification checks.} From the repository root, \texttt{python3 test/\allowbreak{}documentation/\allowbreak{}verify\_\allowbreak{}specification.py -{}-with-hazard} runs eight existing checks: lifecycle guard completeness/disjointness over all $2^5=32$ assignments, pending/readiness behaviour, simultaneous-event precedence, full-population metric examples, the coverage floor, and identical \texttt{SR1}--\texttt{SR9} statements in the \SRS{} and \HA{}. All eight passed during this revision's automated review. The script does not read this plan, compare all constants, or audit references/traceability. The current GitHub Actions workflow builds documents; it does not invoke this script. Jaden Moore will add the specification job by Week 09 (Nov 9) and retain its log. Until then the release reviewer runs it manually. Exit criterion: all eight checks pass, plus the separate inspection below.
    \item \textbf{Manual consistency audit.} The independent verifiers compare every constant in Table~\ref{TblVnVSymbolicConstants} with \SRS{} Table~6, check the requirement/hazard rows in Tables~\ref{TblTraceFunc}--\ref{TblClassCoverage}, and inspect the compiled PDF for unresolved references and instructor comments. They retain a signed checklist and the reviewed commit. Automating these additional checks is planned; a successful run of the existing script does not establish them.
    \item \textbf{Checklist inspection meeting.} All four members meet for 60 minutes before each revision and inspect the \SRS{} against \texttt{SRS-Checklist.pdf} and \texttt{Writing-Checklist.pdf} \cite{SmithCapTemplate}. Section authors present; the verifiers in Table~\ref{TblActivityMatrix} ask four questions of every requirement: (a) can an independent tester write a deterministic pass/fail test from the fit criterion; (b) does it state observable behaviour only; (c) does it preserve \texttt{INV1}--\texttt{INV4} under timeout, cancellation, and malformed input; (d) are its thresholds symbolic and consistent with the \HA{}. Each defect becomes a GitHub Issue. Exit criterion: no open major defect, or a deferral approved by the \TA{}.
    \item \textbf{Peer review.} Team 12 (Issues \href{https://github.com/richy1337/Verity/issues/13}{\#13}--\href{https://github.com/richy1337/Verity/issues/16}{\#16}) drove \MinBaselineDelta{}, opinion and satire abstention, and expanded personas. Team 16 (Issues \href{https://github.com/richy1337/Verity/issues/29}{\#29}--\href{https://github.com/richy1337/Verity/issues/34}{\#34}) drove the pre-admission boundary (\texttt{INV1}), the low-risk summary definition (\texttt{INV2}), and the UI and setup timing constants.
    \item \textbf{\TA{} review.} Requirement testability and scope are reviewed with the \TA{} (Issue \href{https://github.com/richy1337/Verity/issues/17}{\#17}); outcomes are recorded in the \SRS{} Revision History.
\end{enumerate}

\textbf{Feedback triage and closure evidence.} Existing peer feedback is tracked in Issues \href{https://github.com/richy1337/Verity/issues/29}{\#29}--\href{https://github.com/richy1337/Verity/issues/34}{\#34}: \#29 concerns \HA{} references (Richard Han), \#30 the pre-admission boundary and \#31 low-risk terminology (Jaden Moore), \#32 constant naming (Raymond Tao), and \#33 stakeholders/\#34 acronyms (Calvin Salsali). The team's feedback register also records TA, instructor, supervisor if applicable, and internal feedback; absence of feedback from a source is recorded explicitly rather than inventing it.

\subsection{Software Validation}\label{subsec:software-validation}

Verification checks that Verity meets its specification. Validation checks that it solves the problem in the Problem Statement \cite{VerityProbState2026}. Verity has no external client, so validation uses three activities.

\begin{enumerate}[leftmargin=*]
    \item \textbf{Winter Usability and Comprehension Evaluation (\hyperref[test:NFT-2]{NFT-2}, \hyperref[test:NFT-6]{NFT-6}, CD-Winter).} In Weeks 19--21, after Rev 0, the team runs a task-based study with $\ge$ \MinUsabilityParticipants{} unpaid volunteers from the McMaster community, at least three per \SRS{} persona (everyday reader, \ESL{}-aware student editor, community moderator), under the course usability testing guidelines. Each participant signs a consent form; only an anonymous participant ID, task times, and answers are recorded. Each session takes about 30 minutes on a reset team-owned laptop and uses \texttt{FX-USE} (Appendix~\ref{subsec:fixtures}). Task 0 starts with no installed Verity service, Python/CUDA runtime, models, or extension; the release bundle contains the local-service launcher, bundled runtime/model files, unpacked extension, and User Guide. After Task 0, Tasks 1--3 use that installed release build. A separate onboarding item prevents prior exposure to the scored scenarios.
    \begin{itemize}[leftmargin=*]
        \item \emph{Task 0 (installation):} extract the complete release bundle, launch its graphical local-service application, load the extension in developer mode, and run a first check using only the two-page User Guide (\hyperref[req:NFR6]{NFR6}). Developer mode is used because a Chrome Web Store listing requires a registration fee, which \texttt{SRS-C4} excludes.
        \item \emph{Task 1 (\texttt{completed}):} inspect a strong-signal item and identify the status, the primary evidence, and its source tag.
        \item \emph{Task 2 (\texttt{inconclusive}):} inspect a satirical or \ESL{} passage and explain whether Verity accuses the author or abstains, and why.
        \item \emph{Task 3 (\texttt{failed}):} inspect a timeout induced by a controlled provider/proxy delay and state whether the item can be trusted; production test-mode flags remain off.
    \end{itemize}
    Participants then answer Part I and Part II of Appendix~\ref{subsec:usability-survey}. The facilitator reads a fixed script and answers no questions about the result card.

    \textbf{Scoring rule.} Two scorers grade Part I independently against the expected answers in Table~\ref{TblScoringKey}; a third member resolves disagreements. A participant passes a dimension of \hyperref[req:NFR2]{NFR2} only if every item mapped to it is correct, and passes overall only if all three dimensions pass. \textbf{Pass criterion:} the share of participants who pass overall is $\ge$ \MinUnderstandingRate{}. \textbf{Secondary indicators} (reported, not pass/fail for \hyperref[req:NFR2]{NFR2}): mean Part II score $\ge$ \MinLikertMean{}; any participant who reads a \texttt{failed} or \texttt{inconclusive} card as a guarantee or an accusation is logged as an \hyperref[haz:H5]{H5} defect and triggers a \UI{} revision before the Final Demo.

    \textbf{Threats to validity.} With 10 participants, one participant moves the rate by 10 points, so the result supports detection of major comprehension failures, not fine-grained estimates (\SRS{} Table~6 rationale). Volunteers from a university community may have higher digital literacy than the everyday-reader persona; the team recruits at least three participants outside software engineering and reports results per persona. Fixed fixture pages reduce variance but do not cover all real webpages.
    \item \textbf{Real-world corpus validation (\hyperref[test:NFT-1]{NFT-1}, \hyperref[test:NFT-10]{NFT-10}).} Detectors are evaluated on public corpora rather than toy data: held-out RAID \cite{RaidBenchmark2024} and HC3 \cite{HC3Guo2023} slices plus the \ESL{} essays released with Liang et al.\ \cite{Liang2023ESL} for text, and GenImage \cite{GenImage2023} plus team-captured photos re-encoded at JPEG quality 70 and 50 for images.
    \item \textbf{Milestone demonstrations.} The Nov 16--27 \POC{} and Weeks 18--19 Rev 0 demos with the \TA{} and peers validate the workflow, consent wording, and explanation phrasing; feedback is filed as issues and addressed in Rev 1.
\end{enumerate}

The generator supplies the exact boundary, format, capture, privacy-canary, lexicon, and text-injection inputs listed in \texttt{test/fixtures/README.md}.     \item \textbf{Remaining data.} Signed provenance, genre, grounding, image-injection, hostile-page, usability and performance assets and licensed benchmark manifests are completed under the owner/date protocol in Section~\ref{subsec:data-protocol}. Missing data block the affected test.
    \item \textbf{Planned stubs and fault injection.} The harness will read fixed scores and computed-feature records; changing input instructions must not change those records during the controlled \hyperref[test:FT-8]{FT-8} run. Delays, exceptions, and completion barriers are injected only in a test configuration. The release configuration keeps test flags off; release-build timeout tests use a controlled dependency or proxy.
    \item \textbf{Result surface.} Playwright opens the authoritative popup/side panel at its extension URL. Page overlays are non-authoritative mirrors. Release-build keyboard and hostile-page tests operate the actual authoritative controls; an open shadow root in a test build does not substitute for release verification.
    \item \textbf{Timing.} Durations use monotonic clocks. Service deadlines, receipt-to-render latency, cancel-to-banner latency, and terminal-to-cleanup latency are recorded separately. Measurement tolerance is \TimerTolerance{}; it is not extra service processing time.
    \item \textbf{Sink and ownership observations.} Privacy runs monitor stdout/stderr, logs, response bodies, temporary directories, databases, browser extension storage, IndexedDB and caches, including encoded forms of canaries. Backend/extension request-owned objects and task liveness are inspected independently of the buffer registry (\hyperref[test:FT-12]{FT-12}). Public benchmark outcomes are a separate workflow.

\section{Unit Test Description}\label{sec:unit-tests}

This plan precedes the \MG{} and \MIS{} (Rev $-1$ Week 10, Rev 0 Week 16), so this section defines the unit testing scope (Section~\ref{subsec:unit-scope}), the planned suites per component (Section~\ref{subsec:unit-func}), module-level non-functional checks (Section~\ref{subsec:unit-nfr}), and component traceability (Section~\ref{subsec:unit-trace}). After the \MIS{} is complete, each suite gains white-box tests for every exported access routine.

\subsection{Unit Testing Scope and Prioritization}\label{subsec:unit-scope}

Unit tests combine black-box equivalence partitioning and \BVA{} on module interfaces with white-box branch and exception-path coverage.
\begin{itemize}[leftmargin=*]
    \item \textbf{High priority, branch coverage $\ge$ \MinSafetyBranchCov{}:} \texttt{C3} (validation gate), \texttt{C4} (state coordinator), \texttt{C5} (ephemeral privacy handler), and \texttt{C6} (evidence engine). These enforce \texttt{INV1}--\texttt{INV4} and \texttt{SR1}--\texttt{SR9}.
    \item \textbf{Standard priority, line coverage $\ge$ \MinOverallLineCov{}:} \texttt{C1} (capture), \texttt{C2} (result \UI{}), and \texttt{C7} (benchmark harness).
    \item \textbf{Out of scope:} third-party packages listed in Section~\ref{subsec:objectives}. Their boundaries are mocked with pytest-mock and sinon-chrome so the full unit run needs no GPU or network and finishes within \MaxUnitSuiteTime{}.
\end{itemize}

\subsection{Tests for Functional Requirements (Module Level)}\label{subsec:unit-func}

\subsubsection{Components C1 and C2: Capture (UT-C1) and Result Card (UT-C2)}

These suites test TypeScript modules in \texttt{src/\allowbreak{}extension/} with Vitest, jsdom, and sinon-chrome.

\vnvcase{ut:C1}{UT-C1}{Selection Capture, Modality Detection, and Consent Gate}
\begin{itemize}[leftmargin=*]
    \item \textbf{Type:} Functional unit test; dynamic, automatic (Vitest, sinon-chrome).
    \item \textbf{Initial State:} Mocked \texttt{window.getSelection()} and \texttt{chrome.contextMenus} listener.
    \item \textbf{Input:} (1) 300-character text selection inside a parent containing other text; (2) \texttt{HTMLImageElement} with \texttt{src}, \texttt{alt}, and \texttt{naturalWidth = 512}; (3) URL \texttt{chrome://\allowbreak{}settings}; (4) provider configuration with \texttt{consentGranted = false}; (5) a synthetic \texttt{click} event with \texttt{isTrusted = false} on the consent handler.
    \item \textbf{Output:} \texttt{extractScopedSelection()} returns only the selected text or the image \texttt{src}, \texttt{alt}, and dimensions, with no parent or sibling text; \texttt{checkPageEligibility(\allowbreak{}"chrome://\allowbreak{}settings")} returns \texttt{\{eligible: false, reason: "RESTRICTED\_SCHEME"\}}; \texttt{dispatchCheck()} sends nothing to the provider when consent is false; the consent handler ignores the untrusted event.
    \item \textbf{Test Case Derivation:} Branch coverage of capture and guard clauses (\hyperref[req:FR1]{FR1}, \hyperref[req:FR8]{FR8}, \hyperref[req:SR8]{SR8}).
    \item \textbf{How Test Will Be Performed:} \texttt{npm run test:unit} on every commit.
\end{itemize}

\vnvcase{ut:C2}{UT-C2}{Result Card State and Source-Tag Rendering}
\begin{itemize}[leftmargin=*]
    \item \textbf{Type:} Functional unit test; dynamic, automatic (Vitest, jsdom).
    \item \textbf{Initial State:} Result container mounted with active request \texttt{req\_\allowbreak{}active\_\allowbreak{}1}; release configuration.
    \item \textbf{Input:} Responses for all five statuses; a stale response with \texttt{req\_\allowbreak{}id = "req\_old\_0"}; an evidence item without a valid $\mathcal{E}_{\text{src}}$ tag; a \texttt{failed} response carrying a stray low-risk score.
    \item \textbf{Output:} \texttt{renderResultCard()} renders the status badge with icon and text label, the uncertainty, limitations, and verification steps; ignores \texttt{req\_old\_0} without changing the DOM (\texttt{INV3}); omits the untagged item (\SRS{} S.9.1 item 4); renders no low-risk summary for the \texttt{failed} response (\texttt{INV2}); attaches any in-page shadow root in \texttt{closed} mode in the release configuration.
    \item \textbf{Test Case Derivation:} Partition of $\mathcal{S}_{\text{status}}$ and the \texttt{req\_\allowbreak{}id} guard (\hyperref[req:FR3]{FR3}--\hyperref[req:FR7]{FR7}, \hyperref[req:SR1]{SR1}--\hyperref[req:SR5]{SR5}, \hyperref[req:SR7]{SR7}).

\subsubsection{Components C6 and C7: Evidence Engine (UT-C6) and Benchmark Harness (UT-C7)}

\vnvcase{ut:C6}{UT-C6}{Abstention Threshold, Provenance Parser, and Locator Validation}
\begin{itemize}[leftmargin=*]
    \item \textbf{Type:} Functional unit test; dynamic, automatic (pytest, pytest-mock).
    \item \textbf{Initial State:} \texttt{EvidenceEngine} with mocked detector outputs and test value $\tau_{\text{abs}} = 0.15$, so $\tau_{\text{low}} = 0.35$ and $\tau_{\text{high}} = 0.65$.
    \item \textbf{Input:} $\hat{p} \in \{0.05, 0.3499, 0.35, 0.3501, 0.50, 0.6499, 0.65, 0.6501, 0.92\}$; \EXIF{}/\CTwoPA{} dictionaries that are intact, empty, or hash-mismatched; evidence items with valid, missing, and non-resolving locators.
    \item \textbf{Output:} $m(r) \ge \tau_{\text{abs}}$ with consistent signals yields \texttt{completed}, so 0.05, 0.3499, 0.35, 0.65, 0.6501, and 0.92 are \texttt{completed} and 0.3501, 0.50, and 0.6499 are \texttt{inconclusive}; the comparison uses $m(r) \ge \tau_{\text{abs}} -$ \MarginEpsilon{} so that $|0.35 - 0.5|$, which evaluates to $0.15000000000000002$ in binary floating point, is handled consistently. The parser returns \texttt{present\_\allowbreak{}valid}, \texttt{absent\_\allowbreak{}or\_\allowbreak{}stripped}, and \texttt{inconsistent}. Items without a resolving locator or a valid tag are removed before serialization.
    \item \textbf{Test Case Derivation:} \BVA{} on $\pm\tau_{\text{abs}}$ (\SRS{} S.9.1 definition of $v(r)$) and branch coverage of grounding rules (\hyperref[req:FR3]{FR3}--\hyperref[req:FR5]{FR5}, \hyperref[req:FR7]{FR7}, \hyperref[req:FR13]{FR13}, \hyperref[req:SR1]{SR1}--\hyperref[req:SR5]{SR5}).
    \item \textbf{How Test Will Be Performed:} \texttt{pytest test/\allowbreak{}unit/\allowbreak{}test\_\allowbreak{}evidence\_\allowbreak{}engine.py}.
\end{itemize}

\vnvcase{ut:C7}{UT-C7}{Selective and Full-Population Metrics and Counterexamples}
\begin{itemize}[leftmargin=*]
    \item \textbf{Type:} Functional unit test; dynamic, automatic (pytest).
    \item \textbf{Initial State:} \texttt{src/\allowbreak{}benchmark/\allowbreak{}metrics.py}.
    \item \textbf{Input:} (1) The \SRS{} S.9.2 counterexample: 1{,}000 balanced items, 5 correct per class, 990 abstentions; (2) an all-abstention run ($A_0 = 0$); (3) a run with \texttt{failed} outcomes; (4) a hand-computed confusion matrix with subgroup tags; (5) a run with one true class absent.
    \item \textbf{Output:} (1) $F_1^{\text{assessed}} = 1$, $F_1^{\text{all}} = 10/505$, Coverage $= 0.01$, gate fails; (2) $\text{FPR}_{\text{assessed}}$ is \texttt{None} and the gate fails; (3) failures raise ErrorRate and lower Coverage; (4) count-derived numerator/denominator pairs equal the hand-computed rational values exactly, with decimal exports within \MetricTolerance{}; (5) the main two-class benchmark is rejected as an empty required population.     \item \textbf{Test Case Derivation:} Direct check of \SRS{} S.9.2 (\hyperref[req:FR12]{FR12}, \hyperref[req:FR14]{FR14}, \hyperref[req:NFR1]{NFR1}, \hyperref[haz:H10]{H10}).

\subsection{Data Collection, Analysis, and Evidence Freeze Protocol}\label{subsec:data-protocol}

This protocol connects each claim to its selected method, input population, observations, analysis and saved evidence (\texttt{LO\_Plan}). Counts below are planned sampling budgets, not measured results. Exact assets, source revisions and environment records must be committed before execution; an unmet freeze criterion blocks the affected acceptance claim.

\textbf{Main detector benchmark (Raymond Tao; freeze before CD-Fall, Nov 16).} For each retained modality use \BenchmarkTrainSize{} training, \BenchmarkValidationSize{} validation and \BenchmarkTestSize{} test items, balanced by true class within each split. Text draws equal shares from RAID and HC3 in each class/split; images use GenImage authentic and synthetic examples. Retain native inputs meeting the SRS length/dimension/byte bounds before preprocessing. Preserve source labels and their documented authorship/generator provenance; synthetic functional fixtures never enter these splits. If a licensed source cannot supply a required stratum, do not duplicate, upsample ineligible data, or silently shrink the test; record the limitation and obtain the Table~18 scope decision before claiming acceptance.

\textbf{Selection and leakage control.} Pin each dataset URL/revision, license, native item ID and parent source/prompt ID. Group all items from the same source/prompt or image derivation before splitting. Union exact SHA-256 duplicates and near-duplicates: text uses NFKC-normalized, case-folded whitespace-token 5-gram Jaccard similarity $\ge$ \NearTextSimilarity{}; images use a 64-bit perceptual hash (grayscale $32\times32$ resize, two-dimensional cosine transform, median-thresholded top-left $8\times8$ coefficients; preprocessing/library version recorded) with Hamming distance $\le$ \NearImageDistance{}. Empty/too-short normalized comparisons are inspected manually. Rank source groups by SHA-256 of \texttt{42|dataset|group\_id}; in that order allocate whole groups to train, validation, then test quotas while preserving class/source strata. Deterministically choose the required examples within allocated groups; all unused members of a group remain excluded from other splits. Retain the grouping report and rejected-item reasons. The frozen manifests list every selected ID, split, label, subgroup, native bounds and byte hash. This is the required fetch/split algorithm; its implementation is scheduled, not claimed to exist already.

\textbf{Thresholds, calibration and comparison.} Freeze one candidate checkpoint per retained modality, exact dependency locks, preprocessing/configuration hashes, baseline settings and $\tau_{\text{abs}}$ after validation. Test outcomes cannot select them. \hyperref[test:NFT-1]{NFT-1} retains all four SRS gates on its fixed two-class test. Also report Brier score, a reliability diagram with \CalibrationBins{} equal-width bins, expected calibration error (ECE), per-bin counts and a risk--coverage curve as descriptive diagnostics. These diagnostics examine whether a displayed calibrated score is supported; they add no unapproved numerical acceptance gate. Undefined scores are reported explicitly. Separate raw feature outputs, outcomes and counts permit independent recomputation; exact count metrics use numerator/denominator pairs and decimal exports use \MetricTolerance{}.

\textbf{Fairness data (Raymond Tao; freeze Nov 16).} Use at least \MinFairnessSliceSize{} source-distinct authentic examples each of native prose, Liang et al.\ ESL prose \cite{Liang2023ESL}, and licensed formal academic prose; record source and subgroup annotation rationale. No fairness item or near-duplicate is used to train/calibrate a detector. For image robustness, collect at least \MinFairnessSliceSize{} consented source-distinct camera photos and derive quality-70 and quality-50 JPEG copies. Keep each original and both recompressions in the held-out family. Report the three image slices separately and retain family IDs so paired copies are not presented as independent samples. The minimum supports a feasible coarse error audit; 95\% Wilson intervals expose the uncertainty of small proportions. With zero assessed negatives or an undersized group, report insufficient evidence and do not claim a completed audit. Authentic-only slices support FPR/negative coverage, not a two-class F1 claim.

\textbf{Performance inputs (Jaden Moore; freeze before Rev 0).} Text item $k=0,\ldots,99$ has $150+\lfloor9850k/99\rfloor$ Unicode code points. For images use 25 cases each of PNG, JPEG quality 90, JPEG quality 50, and lossless WebP, with square dimension $64+\lfloor4032j/24\rfloor$ for $j=0,\ldots,24$. Replace the final PNG case with a valid $1024\times1024$ PNG padded to exactly 10{,}000{,}000 bytes; the other formats retain the maximum dimension case. All encoded files must remain within the byte limit. Commit exact file IDs/hashes and execute in manifest order with one cold-start observation followed by 99 warm requests. Retain timestamps, sizes, statuses and p50/p90/p95/p99 summaries; keep failed requests in the denominator.

\textbf{Remaining functional/study assets and independent review.} Richard Han freezes adversarial, grounding and privacy assets by Week 10 (Nov 16); Raymond Tao freezes approved provenance photos/signing recipes and the real-detector abstention set by the same date. Calvin Salsali freezes the hostile-page attack harness by Week 16 (Jan 18), and the facilitator script, unseen study pages, expected primary evidence/source tag and scorer sheet before recruitment in Week 19 (Feb 8). Jaden Moore supplies the packaged-service/installation procedure by Week 18 (Feb 1). The independent verifier in Table~\ref{TblActivityMatrix} checks every manifest and recipe. The detailed construction instructions in \texttt{test/fixtures/README.md} are part of this input contract.

\textbf{Feasibility and evidence.} Baseline/candidate comparisons are restricted to the declared fixed splits and one frozen candidate per modality at an acceptance run; exploratory training uses training/validation data only. Raymond budgets at most four CPU-hours per modality per acceptance run on the recorded service profile and records actual resource use. If the budget or an SRS gate cannot be met, a TA-reviewed scope decision is required rather than an unbounded search or threshold relaxation. Richard indexes evidence by commit/test ID under \texttt{artifacts/vnv/<run-id>/}: environment/configuration records, fixture/split hashes, observed and expected results, raw counts/outcomes, assertion logs, privacy ownership observations, accessibility/browser checklists, and anonymized study answers/scores. Raw live-user inputs are never included. Every case is passed, failed, blocked or not run; a listed requirement without executed evidence is not reported verified.
